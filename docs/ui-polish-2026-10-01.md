## 验证

- 全量自动化测试：Core 12、Infrastructure 28、App 61，共 101 项通过，0 失败、0 跳过。
- 新增回归覆盖：加载失败后重试、保存期间取消保护、放弃设置草稿、无效下载地址的就地反馈、取消安装后再次安装，以及自动重试与耗尽状态的区分。
- 渲染检查：主窗口 900 与 1180 宽度、查词页 560 与 880 宽度、浮窗紧凑/展开/长文本/已收藏状态、同步多个状态，以及 900×600 编辑与设置草稿状态。检查最小窗口的保存区与放弃修改入口，确保它们位于可用高度内。
- 修正测试隔离：词典安装/清理会调用进程级 SQLite `ClearAllPools`，因此这类测试不能与其他数据库测试并行。本轮遇到的 Anki 测试连接释放错误在单独运行时通过，将词典测试放入不并行测试集合后全量通过。这是测试隔离调整，不表示已经验证或修复真实运行中的所有数据库并发行为。

本轮验证包含自动化与离屏渲染检查，没有将其计为 PDF、浏览器、Word 或真实 Anki 的场景验收。此前稳定性验收项目仍以 `v0.2.2-stability-validation.md` 中的待验证状态为准。

## 打开设置页异常修复 · 2026-10-01

- 问题：真实应用打开设置页时，原生控件模板抛出 `XamlParseException`，提示空值不是 `FontSize` 的有效值。
- 原因：窗口完成 `InitializeComponent` 后移除了本地 `DesignSystem` 字典，模板延迟加载时无法正确解析其中的资源；独立布局测试没有应用级资源，未覆盖该路径。
- 修改：`WpfUiResourceScope.PreferApplicationResources` 保留本地 `DesignSystem` 字典，继续保留 WPF-UI 原生输入控件模板。
- 回归：`SettingsRendersWithActualApplicationResources` 加载应用同样的资源与强调色，渲染并切换四个页面，调用 `ShowSettings` 显示窗口；修复前复现相同字号异常，修复后通过。
- 结果：完整 Release 测试 102 项通过（Core 12、Infrastructure 28、App 62）。
- Debug 程序已重新构建（0 警告、0 错误），用户正常退出旧程序后已重启新版；启动日志确认初始化完成并驻留托盘。当前自动化工具无法定位托盘菜单，实际个人配置下打开设置页的最后一步由用户操作。

## 桌面图标留白调整 · 2026-10-01

- 问题：图标主体只占画布宽度的 87.5%，在托盘与任务栏中显得偏小。

- 托盘：直接从内嵌 ICO 选择系统小图标尺寸，覆盖 16、20、24、32 等常见 DPI，避免优先提取 exe 大图后缩小。
- 验证：检查 16、24、32 像素前后对照，ICO 的 10 个尺寸帧完整；Release 构建 0 警告、0 错误，App 回归 62 项通过，`git diff --check` 通过。当前 Debug 进程未替换，退出后运行新构建的 Release 程序才能检查实际托盘与任务栏效果。

## 查词浮窗顶部操作细化 · 2026-10-01

- 问题：钉住标签重复显示状态；朗读、钉住、关闭按钮边框与图标比例不统一，默认焦点虚线显得杂乱。
