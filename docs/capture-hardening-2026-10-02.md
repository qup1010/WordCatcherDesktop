# 取词可靠性改进 · 2026-10-02

当前版本号仍为 0.2.1，本次没有发布 v0.2.2。

## 问题、修改与验证

| 问题 | 修改 | 验证结果 |
| --- | --- | --- |
| 恢复旧内容可能覆盖用户随后复制的新内容 | `NativeClipboardBackup.Restore` 在 `OpenClipboard` 成功后比较本次复制的序号，在同一次锁内清空和恢复，避免比较与写回之间的竞争。 | 回归覆盖语境读取期间再次复制、恢复边界再次复制；隔离窗口站中的真实 Win32 测试确认新内容保留。 |
| 原剪贴板为空时跳过恢复 | 空快照也执行受序号保护的 `EmptyClipboard`。 | 自动回归和隔离 Win32 测试均确认恢复为空。 |
| 仅备份部分常见格式 | 备份独立原生内存格式及位图/增强 metafile 句柄；保留 HTML、RTF、文件列表、DIB 和可复制的自定义二进制内容。无法完整读取或独立复制时停止，不能使用部分快照继续模拟复制。 | 隔离测试逐项比较 Unicode、HTML、RTF、文件列表、DIB 和自定义二进制字节；不支持的私有格式保留原样并中止。位图/增强 metafile 句柄路径未单独进行真实应用验收。 |
| 所有取词都模拟复制 | `NativeSelectionCapturePlatform` 优先读取来源窗口内的 UIA 单一选区；成功后直接返回。无法提供语境时使用选区自身，无法读取选区时回退复制。 | 回归确认 UIA 成功不备份、不复制、不恢复剪贴板；读取超时能回退。PDF、Word、浏览器 provider 兼容性仍待真实验收。 |
| provider 慢调用可能阻塞热键 | UIA 调用始终放在后台 STA，每次等待最多 750 ms；最多保留一个未结束的 provider 调用，其他请求回退复制。 | 回归确认超时后能完成复制取词。外部 provider 的挂起调用无法被强行终止。 |
| 等待按键释放期间或读取过程中切换窗口 | 等待前记录来源，等待后、复制前、复制等待期间、语境读取前后均校验前台 HWND 与进程；UIA 只读取属于来源窗口的焦点祖先链。 | 回归覆盖松键期间和语境读取期间切换窗口。 |
| 把任意剪贴板变化当成本次复制 | 在锁住剪贴板后验证序号和所有者进程；拒绝未知或其他进程的内容。 | 回归和隔离 Win32 测试覆盖不匹配的所有者与序号。 |
| 失败提示统一、难以判断原因 | `CaptureException` 区分空选区、复制超时、剪贴板忙、内容改变、窗口切换、不支持格式、按键未松开、长度超限和输入注入失败；热键入口显示对应提示，重复请求保持静默。 | 回归覆盖各主要失败分支、取消后的恢复和锁释放。注入失败只描述为“可能存在权限限制”，不直接断言为 UIPI。 |
| 重复单词误定位 | 保留 UIA 选区前缀长度来计算实际偏移，不使用首次字符串匹配。 | 回归确认第二个 `ocean` 的偏移指向第二次出现。 |

## 明确边界

- `Ctrl+C` 和剪贴板更新之间没有应用可用的事务标识；同一个来源进程内同时发生的另一次复制，仍可能无法区分。这些校验减少误取风险，并不意味着模拟输入与窗口切换原子化。
- 某些应用通过代理进程写剪贴板，所有者校验可能保守拒绝；需要在真实应用中记录并调整，不能直接放宽所有者校验。
- 调色板、旧式 metafile、需要原应用回调/对象的格式、无法读取的延迟格式，以及超过 64 MiB 或 256 格式的备份，会中止复制。UIA 成功时不受这些剪贴板限制影响。
- 系统 API 或剪贴板持续占用仍可能导致恢复失败，失败会记录日志；不能承诺任意格式、任意应用完全恢复。
- 未进行 PDF、Word、真实浏览器与 Anki 的场景验收。`v0.2.2-stability-validation.md` 中对应项目继续保持待验证。
